# ExMesh 정보 기반 단순화 개선: 광도 시차 이차오차(PPQ)와 생성 모델 비교

UE5 플러그인 연동 담당자용 문서입니다. 다음 세 가지를 다룹니다.

- 무엇을 왜 바꿨는지
- 어떻게 호출하는지
- 결과가 어떤지

이전 Sobel 연동 안내는 [SOBEL_PLUGIN_MIGRATION.md](SOBEL_PLUGIN_MIGRATION.md)에 있습니다. 새 옵션을 지정하지 않으면 출력은 이전과 같습니다. 텍스처는 바이트 단위로 같고, OBJ는 파일 이름이 들어가는 `mtllib` 줄만 다릅니다(8.6절).

## 0. 요약

- **새 방법 PPQ(다시점 광도 시차 이차오차)**: 단순화로 원본 면이 법선 방향으로 h만큼 어긋날 때 촬영 시점들에서 생기는 렌더 오차를 1차 테일러 전개로 계산한 면 가중치입니다.
  - 오차가 Σ_f W_f h_f²로 정리되어 **Wild QEM과 같은 이차형식**이 됩니다. 그래서 Wild 구조를 그대로 두고 더할 수 있습니다.
  - ExMesh의 촬영 카메라와 사진에 맞춘 외관을 씁니다. 가중치는 λ=1로 고정했고 튜닝하지 않았습니다.
- **결과**(팀 평가기, 장면 2 × 예산 3 × 시점 2종 = 12개 조건):
  - Wild 대비: **12개 조건 모두** PSNR이 유의하게 올랐습니다(+0.06~+0.67 dB, 평균 +0.29 dB). 같은 조건에서 Sobel의 평균 이득은 +0.13 dB였습니다.
  - Sobel 대비: **12개 조건 모두** 유의하게 우세합니다(+0.08~+0.31 dB, 평균 +0.17 dB). Sobel이 Wild보다 나빴던 scan83 1만 면에서도 PPQ는 Wild보다 좋았습니다.
  - 대가: 평균 표면 거리가 4~7% 늘어납니다.
  - UE5처럼 밉맵 + 안티에일리어싱으로 렌더한 보조 평가에서도 PPQ가 12개 조건 모두에서 Wild와 Sobel보다 유의하게 좋았습니다.
- **텍스처 정제**(`appearance_refine.py`, 선택):
  - 밉맵 렌더에서는 PSNR +1.4~4.7 dB이고 LPIPS도 좋아집니다.
  - 팀 평가기에서는 PSNR +0.2~0.9 dB지만 LPIPS가 나빠집니다. 원본 렌더의 앨리어싱 입자를 지우기 때문입니다(4.3).
  - 첫 버전의 이음새 버그는 찾아서 고쳤습니다(8.1).
- **권장 파이프라인**: ExMesh → PPQ 에너지(GPU 약 2초) → Wild `--method photometric` → (선택) 정제 `--mode full`(GPU 약 30초)
- **생성 모델(Tripo/Hunyuan)**: ExMesh가 기하는 2.9~5배 정확하고, 사진 대비 PSNR은 7~9 dB 높습니다. Hunyuan은 라이선스가 한국을 제외합니다. **ExMesh 유지를 권장합니다**(5장).

## 1. 연구 범위 정리

원래 큰 그림은 **"ExMesh가 가진 정보로 Wild 단순화를 개선한다"**였습니다. 이 문서의 새 방법도 이 틀 안에 있습니다. PPQ는 ExMesh의 **촬영 카메라 분포**와 **원본 메시 렌더(=사진에 맞춰 최적화된 외관)**를 사용합니다. 일반 메시 단순화기는 이 정보를 갖고 있지 않습니다.

Tripo/Hunyuan 비교(5장)는 연구 주제가 아니라 **"왜 생성 모델이 아니라 ExMesh인가"를 뒷받침하는 근거 실험**으로 두는 것을 권장합니다. 플러그인도 "사진 여러 장 → ExMesh → ExMesh 정보 기반 LOD 생성"으로 정리하면 범위가 다시 선명해집니다.

## 2. 새 방법: 다시점 광도 시차 이차오차 (Photometric Parallax Quadric, PPQ)

### 2.1 아이디어

Wild는 단순화한 표면의 텍스처를 **원본 표면의 가장 가까운 점**에서 가져옵니다(successive mapping). 그래서 단순화 때문에 원본 면 f가 법선 방향으로 h만큼 어긋나면, 그 면의 텍스처도 h·n_f만큼 이동한 것처럼 보입니다.

- 정면에서 보면 이 이동이 시선과 평행하므로 화면에서 거의 보이지 않습니다.
- 비스듬히 보면 텍스처가 화면에서 미끄러집니다(시차, parallax).
- 그 위치에 색 경계가 있으면 렌더 오차가 납니다.

원래 Wild에는 이런 외관 가중치가 없습니다. 우리가 먼저 시도한 Sobel 가중치(팀 자체 휴리스틱)는 이 현상을 "경계 근처 면은 덜 줄이자"는 **경험 규칙**으로 근사한 것이었습니다. PPQ는 같은 현상을 **렌더 오차의 1차 테일러 전개로 정확히 계산**합니다. 따라서 비교 구도는 Wild(원 논문, 기준선) → Sobel(우리의 1차 시도) → PPQ(제안)입니다.

### 2.2 유도

- 촬영 시점 v의 투영을 π_v라 하고, 3D 점 X에서의 2×3 야코비안을 J_v = ∂π_v/∂X라 합니다.
- 면 f가 법선 방향으로 h 이동하면 그 텍스처의 화면 위치는 J_v n_f h(픽셀)만큼 움직입니다.
- 따라서 그 면이 보이는 픽셀 x의 렌더 색 변화는 1차 근사로 다음과 같습니다.

  ΔI_v(x) ≈ −∇I_v(x) · J_v(X_x) n_f · h

- 모든 촬영 시점과 픽셀의 제곱 오차를 합하면

  E = Σ_v Σ_x ‖ΔI_v(x)‖² = Σ_f W_f h_f²,  W_f = Σ_v Σ_{x∈Ω_v(f)} Σ_{c∈RGB} ( ∇I_{v,c}(x) · J_v(X_x) n_f )²

- Wild의 memory plane quadric에서 h_f = n_fᵀv + d_f = p_fᵀ[v;1]이므로 E(v) = [v;1]ᵀ(Σ_f W_f p_f p_fᵀ)[v;1]입니다. **기존 QEM과 같은 이차형식**이므로 Wild 구조(memory plane Q, boundary area Q, virtual edge, successive mapping)를 바꾸지 않고 그대로 더할 수 있습니다.
- 최종 면 가중치(기하항 + 광도항):

  Q_f ∝ A_f (1 + λ ρ_f / ρ̄) p_f p_fᵀ,  ρ_f = W_f / A_f,  ρ̄ = Σ_f W_f / Σ_f A_f

  - λ = 1이면 광도항과 기하항의 **전체 에너지가 같아집니다**("equal energy").
  - 결과를 보고 고른 값이 아니라 처음부터 고정한 값입니다(튜닝 없음).
- 카메라 좌표 (x, y, z), 카메라 좌표계 법선 n_c = Rᵀn에서

  J_v n = ( f_x (n_x z − x n_z) / z²,  f_y (n_y z − y n_z) / z² )

  - 정면(n ∥ 시선)이면 0이 됩니다.
  - 물체/배경 실루엣에서는 ∇I가 크고 J n이 실루엣에 수직이므로 **실루엣 보존이 자동으로 들어갑니다**.

### 2.3 Sobel 가중치와의 차이

| | Sobel λ4 (팀의 이전 시도) | PPQ (신규) |
|---|---|---|
| 근거 | 경험 규칙: 경계 면을 덜 줄인다 | 렌더 오차의 1차 테일러 전개 |
| 이미지 기울기 | 크기 \|∇I\|, 방향 무시 | 화면 이동 방향 성분 (∇I·J n)²만 |
| 시점 각도 | 무시 | 포함. 정면에서는 이동이 안 보여 0 |
| 집계 | 시점 평균 → P95 정규화 → [0,1] 클리핑 | 모든 시점·픽셀의 에너지 합 |
| 실루엣/물체 경계 | 간접 | 자동 포함 |
| 하이퍼파라미터 | λ(=4, scan24에서 선택), σ, 커널, P95 | λ=1 고정. σ=1은 Sobel과 동일 |
| 가중치 분포 (scan24) | 중앙값 1.69, P99 4.67, 최대 5 | 중앙값 1.10, P99 15.8, 최대 112 |

- 두 가중치의 순위 상관(Spearman)은 0.81(scan24) / 0.79(scan83)입니다. 비슷한 곳을 중요하게 보지만, PPQ는 대부분의 면을 기하 QEM에 가깝게 두고 **소수의 민감한 면에 예산을 집중**합니다.
- 비교 그림: `deliverables/enhanced_simplification/scan24_face_weights.png` (원본 렌더 | Sobel | PPQ, log 스케일).
  - Sobel은 지붕 기와 무늬에도 높은 값을 줍니다.
  - PPQ는 창틀, 계단식 박공 모서리, 실루엣에 집중합니다.

### 2.4 구현 (`photometric_quadric_weights.py`)

- 원본 OBJ를 nvdiffrast로 각 촬영 카메라(`cameras.json`)에서 렌더합니다. 원본 텍스처를 mipmap으로 사용합니다.
- 렌더 결과에서 ∇I를 구합니다(Gaussian σ=1 → Sobel 3×3/8). Sobel 점수와 같은 전처리 척도입니다.
- 픽셀마다 면 ID, 3D 위치, J n을 계산한 뒤 W_f에 누적합니다(GPU, scan24 49뷰 기준 **약 2초**).
- 출력: 원본 면 순서의 에너지 밀도 ρ_f = W_f/A_f(`.npy`, float64)와 요약 `.json`.
- 가짜 기울기를 막는 처리가 세 가지 있습니다.
  1. **가림 경계**: 필터 반경(4 px) 안에 1% 이상 가까운 표면이 있으면 그 픽셀은 제외합니다. 그 대비는 앞의 물체가 만든 것이고 뒤 면을 움직여도 변하지 않습니다.
  2. **이미지 테두리**: 테두리 4 px는 제외합니다. 컨볼루션의 zero padding이 가짜 경계를 만들어, scan24처럼 물체가 화면 밖으로 잘린 시점에서 지붕을 가로지르는 줄무늬 가중치가 생겼습니다.
  3. **아틀라스 edge padding**: 렌더 전에 원본 텍스처의 빈 영역을 가장 가까운 차트 색으로 채웁니다. 채우지 않으면 검은 배경이 mip 레벨에서 UV 이음새를 따라 번져 가짜 기울기가 생깁니다(8.2).
  - 1·2는 가중치를 시각화해서, 3은 정제 버그(8.1)를 추적하다가 발견했습니다.
- `--source photo`를 주면 렌더 대신 실제 촬영 사진(알파 = 물체 마스크)의 기울기를 씁니다. 기본값은 render입니다. 단순화의 목표가 "원본 메시의 외관 보존"이기 때문입니다.

## 3. 텍스처 전달 개선 (보조 옵션)

PPQ는 **어떤 간선을 어디로 합칠지**를 정합니다. 단순화 후 텍스처를 다시 굽는 단계에도 개선 여지가 있어 함께 구현했습니다. 이 둘은 PPQ와 독립이며 Sobel/Wild와도 같이 쓸 수 있습니다.

### 3.1 슈퍼샘플링 전달 (`--texture_supersample K`)

- 기존 bake는 1024² 아틀라스의 텍셀 중심 한 점만 2560² 원본 텍스처에서 가져옵니다. 이 방식은 aliasing을 만듭니다.
- K×K 하위 표본을 collapse history로 추적해 평균합니다(box filter). 기본 K=1은 기존과 같습니다.
- K=3은 bake 시간이 약 6배 늘어납니다(약 50초 → 5분). 3.2를 쓸 거라면 필요 없습니다(4장).

### 3.2 외관 기반 정제 (`appearance_refine.py`, GPU 후처리)

- 단순화된 메시의 텍스처 T(와 선택적으로 정점 오프셋 δ)를 원본 렌더에 맞춰 최적화합니다.

  min_{T,δ} E_{v∼S²} ‖ R(V+δ, T; v) − R_orig(v) ‖² + λ_L ‖L δ‖²

  - v는 **전 방위 무작위 시점**입니다. 촬영 카메라나 평가 카메라는 쓰지 않습니다.
  - L은 uniform Laplacian입니다.
  - Hasselgren et al., *Appearance-Driven Automatic 3D Model Simplification* (EGSR 2021)에서 착안했습니다. 다만 여기서는 Wild 결과에서 출발하는 후처리입니다.
- `--mode tex`는 텍스처만, `--mode full`은 텍스처와 정점을 함께 최적화합니다.
- 위상, UV, 면 순서는 그대로이므로 **UE5 임포트 경로가 바뀌지 않습니다**.
- R은 nvdiffrast 렌더입니다(trilinear mipmap + 안티에일리어싱). UE5가 텍스처를 보여 주는 방식과 같은 계열입니다.
- 원본과 결과 아틀라스는 모두 **edge padding**합니다. 차트 밖 텍셀은 가장 가까운 차트 텍셀을 복사합니다.
  - 패딩이 없으면 검은 배경이 mip 레벨에서 차트 경계로 번집니다. 그러면 목표 이미지에 이음새가 생기고, 정제가 그것을 학습합니다(8.1절의 v1 버그).
- 하이퍼파라미터(2000 iter, λ_L=10, lr)는 **별도 시드의 무작위 검증 시점 24개로만** 정했고, 평가 카메라는 보지 않았습니다.
- 소요: 약 30초, VRAM 약 1.2 GB.

### 3.3 가시성 가중치 (`--visibility`, 참고용)

- Zhang & Turk(2002)의 visibility-guided simplification 방식입니다. 구 방향 128개에서 가려지지 않은 비율로 면 가중치를 곱합니다.
- scan24 메시는 가려진 면이 거의 없습니다(평균 0.81, 0.5 미만 면적 6%). 그래서 효과가 작았고 부호도 일정하지 않았습니다(Wild 대비 −0.30~+0.11 dB, 4.2).
- PPQ가 촬영 시점의 가시성을 이미 포함하므로 기본 파이프라인에는 넣지 않았습니다.

## 4. 결과

### 4.1 평가 방법

- **평가기**: 이전 Sobel 실험과 같은 `evaluate_mesh_preservation.py`(CPU 레이캐스트, bilinear 텍스처, 안티에일리어싱 없음)입니다.
  - 기준 이미지는 단순화 전 ExMesh 메시의 렌더입니다. 즉 **단순화가 원본 외관을 얼마나 보존하는지**를 잽니다.
  - 기하는 표면 샘플 사이의 평균 거리와 HD95입니다(bbox 대각선 대비 %).
- **평가 시점** 두 종류:
  - **촬영 카메라 ±5°**: scan24는 기존 Sobel 실험의 고정 포즈 98개(49 카메라 × ±5°)를 그대로 썼습니다. scan83은 같은 규칙으로 만든 128개(64 카메라 × ±5°)입니다. 해상도는 1/2입니다.
  - **전 방위 고정 60뷰**: 구 전체에서 고정 시드로 뽑은 60개, 768²입니다(`make_orbit_cameras.py`). 게임에서는 촬영하지 않은 방향에서도 보이므로 추가했습니다.
- **목표 면 수**: 20,000 / 10,000 / 5,000입니다. 원본 약 21만 면의 9.6% / 4.8% / 2.4%입니다.
- **통제 조건**: 모든 방법이 같은 Wild 구현, 같은 bake(K=1), 같은 1024² 아틀라스를 씁니다. 4.2절에서는 **간선 비용(면 가중치)만** 다릅니다.
- **통계**: 같은 시점끼리 차이를 구합니다.
  - 촬영 카메라 단위(±5° 두 장을 한 묶음)로 cluster bootstrap 95% 구간을 냈습니다.
  - 표의 \*는 구간이 0을 포함하지 않는다는 뜻입니다.
- 장면 2개, 예산 3개, 시점 2종의 **12개 조건**입니다. 장면이 2개뿐이라 일반화에는 한계가 있습니다.

### 4.2 간선 비용: PPQ vs Wild vs Sobel (핵심 결과)

표 읽는 법:
- PSNR 단위는 dB입니다. ΔPSNR은 [95% 구간]을 함께 적었고, \*는 유의합니다.
- ΔLPIPS×10³은 LPIPS **감소량**입니다(양수 = 좋아짐).
- 마지막 열은 평균 표면 거리의 PPQ/Wild 비입니다(1.05 = 5% 증가).

### 4.3 텍스처 전달·정제

이 절의 방법들은 **텍스처 필터링**을 바꿉니다.

팀 평가기는 mipmap과 안티에일리어싱 없이 렌더합니다. 그래서 기준 이미지(원본 2560² 텍스처를 화면에서 3~5배 축소)에 앨리어싱 입자가 그대로 남습니다. 필터링된 텍스처는 이 입자를 재현하지 못하므로, 이 평가기에서는 PSNR이 오르고 LPIPS는 나빠지는 경향이 있습니다.

그래서 같은 포즈를 UE5가 텍스처를 보여 주는 방식으로 다시 렌더한 **보조 평가**(`evaluate_engine_like.py`)를 함께 싣습니다. 차이는 다음뿐입니다.
- trilinear mipmap, edge padding, 2×2 슈퍼샘플링을 씁니다.
- 지표 코드와 크롭은 팀 평가기와 같습니다.

공정성 주의: 이 보조 평가는 팀 평가기 결과를 본 뒤 추가했습니다. 또 정제는 이 렌더러와 같은 계열로 학습했으므로 정제에 유리한 조건입니다(학습 시점과 평가 시점은 겹치지 않음).

### 4.4 권장 설정

- **기본**: `--method photometric`(PPQ). 추가 비용은 GPU 약 2초입니다.
- **UE5에 넣을 최종 LOD**: 여기에 `appearance_refine.py --mode full`(GPU 약 30초)을 더하는 것을 권합니다.
  - 출력 텍스처가 edge padding되어 있어 UE5 mip에서 검은 번짐이 없습니다(6.3).
  - 다만 팀 평가기의 LPIPS 기준으로는 나빠지므로, 정량 보고에는 두 평가를 함께 싣고 UE5에서 육안 확인하세요.
- SS3와 가시성 가중치는 기본값으로 쓰지 않습니다.
- 한계: 장면이 2개(DTU scan24 건물, scan83 인형)뿐입니다. 다른 재질과 형태에서의 일반화는 검증하지 않았습니다.

## 5. 생성 모델(Tripo/Hunyuan)과 ExMesh 비교

"ExMesh 대신 이미지→3D 생성 모델로 메시를 만들면 어떤가?"를 확인한 실험입니다. 재현 방법은 [`alt_models/README.md`](../alt_models/README.md)에 있습니다.

### 5.1 조건

- **생성 모델**: 촬영 사진 1장(scan83 51번, scan24 23번 시점)을 입력으로 각 모델의 공식 기본 설정으로 실행했습니다.
- **ExMesh**: 같은 장면의 사진 49장 전체로 학습한 결과입니다. 입력 정보량이 다르다는 점이 이 비교의 요점입니다.
- **정렬**: 생성 결과는 크기·자세가 임의라서 GT 점군에 유사변환(스케일·회전·이동)으로 맞췄습니다. GT를 쓰는 **오라클 정렬이라 생성 모델에 유리한 조건**입니다.
- **기하 지표**: DTU 공식 chamfer(mm)입니다.
- **외관 지표**: 생성 모델의 입력 시점을 뺀 모든 촬영 시점에서 실제 사진과 비교했습니다.
  - 물체 마스크 영역 PSNR, bbox 크롭 SSIM·LPIPS, 실루엣 IoU를 구했습니다.
  - ExMesh는 이 사진들로 학습했으므로, 이 값은 일반화 성능이 아니라 **실제 물체에 대한 충실도**입니다.
- **제외한 모델**:
  - Meshy: 오픈소스가 아닌 유료 API이고, 이미지를 외부 서버로 보내야 합니다.
  - Stable Fast 3D: HF 접근 승인(gated)이 필요합니다.
  - TRELLIS: Linux 전용 의존성이 있습니다.

  - 같은 촬영 카메라에서 렌더한 이미지입니다.

### 5.3 해석

- **기하 정확도**: ExMesh가 가장 나은 생성 모델보다 scan83에서 2.9배(Hunyuan3D-2mini-turbo 대비), scan24에서 5배(Hunyuan 대비) 정확합니다. 오라클 정렬을 줬는데도 그렇습니다.
- **외관**: 생성 모델은 입력 사진에 보이지 않는 면을 그럴듯하게 지어냅니다.
  - scan24(건물)에서는 모든 입력 사진이 건물을 잘라서 보여 줍니다. 그래서 Hunyuan은 실제와 다른 창문을 만들었고, 조명이 빠진(delit) 색을 냅니다.
  - TripoSR는 텍스처가 흐립니다.
  - 사진 대비 PSNR은 ExMesh보다 7~9 dB 낮습니다.
- **속도**: 생성 모델의 확실한 장점입니다(20~90초 대 약 15분).
- **VRAM**: Hunyuan 기본 설정은 9.1 GB입니다.
  - 경량 설정(2mini-turbo, 5 step, FlashVDM)은 형상 생성이 2.6초, 최대 4.1 GB입니다. 정확도는 기본 설정과 비슷하거나 조금 나았습니다.
- **라이선스**: Tencent Hunyuan 3D 2.0 Community License는 적용 지역에서 EU·영국·**대한민국**을 제외합니다(1(l), 5(c)).
  - 한국에서 모델이나 그 출력물을 쓰는 것 자체가 라이선스 범위 밖이므로 **플러그인 후보가 될 수 없습니다**.
  - TripoSR는 MIT입니다.

### 5.4 권장: ExMesh 유지

1. 목표가 "실제 물체를 게임 에셋으로"라면 ExMesh가 정확도와 사진 충실도에서 압도적입니다.
2. 연구 주제(ExMesh 정보 기반 단순화)는 ExMesh의 **촬영 카메라와 사진에 정합된 외관**을 전제로 합니다. 생성 모델 출력에는 촬영 카메라가 없어 PPQ가 성립하지 않습니다(6.3).
3. 생성 모델을 넣는다면 "사진 한 장 빠른 미리보기" 같은 부가 기능이면 충분합니다. 그 경우에도 MIT인 TripoSR를 쓰세요. Hunyuan은 쓰지 마세요.

## 6. UE5 플러그인 연동

### 6.1 실행 순서

```powershell
# 0) 기존과 동일: ExMesh 학습 → OBJ export (학습 폴더에 cameras.json이 함께 생성됨)
python train.py -s <scene> -m <model_dir>
python scripts/export_obj.py --model_path <model_dir> --iteration 10000

# 1) [신규, GPU 약 2초] PPQ 에너지 계산: export한 OBJ와 학습 카메라 사용
python simplification/photometric_quadric_weights.py `
  --mesh <model_dir>/export/mesh_iter_10000.obj --cameras <model_dir>/cameras.json `
  --output <model_dir>/photometric_energy.npy

# 2) [CPU 약 3~4분] Wild 단순화 + PPQ
python simplification/wild_simplify_xatlas_verified.py `
  --input <model_dir>/export/mesh_iter_10000.obj --texture <model_dir>/export/mesh_iter_10000.png `
  --output <out>/lod.obj --ratio 0.05 --method photometric --face_energy <model_dir>/photometric_energy.npy

# 3) [선택, GPU 약 30초] 외관 기반 정제
python simplification/appearance_refine.py --reference <model_dir>/export/mesh_iter_10000.obj `
  --input <out>/lod.obj --output <out>/lod_refined.obj --mode full
```

- 모든 단계는 기존 `exmesh` conda 환경 하나로 돌아갑니다(torch 2.5.1+cu121, nvdiffrast 0.4.0, open3d, xatlas, numba).
- 2단계만 CPU이고 1·3단계는 CUDA GPU가 필요합니다.
- 2단계는 기존처럼 `.ablation_env`(GPU 없음)에서도 실행됩니다.

### 6.3 파일과 성공 판정

- 배포 파일(같은 폴더):
  - `wild_simplify_xatlas_verified.py`, `obj_geometry_topology.py`
  - `photometric_quadric_weights.py`, `appearance_refine.py`: 앞의 것이 뒤의 것을 import하므로 함께 배포합니다.
- 출력 형식은 기존과 같은 `<stem>.obj`, `<stem>.mtl`, `<stem>_texture.png` 3개입니다.
  - 단순화기는 추가로 `<stem>.statistics.json`(method, 시간, 옵션)과 `<stem>.input_topology.json`을 씁니다.
  - 정제는 `<stem>.complete.json`(검증 PSNR 변화, 시간, VRAM, 정점 이동량)을 **마지막에** 씁니다.
- 성공 판정은 프로세스 종료 코드 0 + 세 파일 존재로 합니다. 로그 문자열로 판정하지 마세요.
- PPQ 에너지는 **단순화기에 넣을 OBJ와 같은 파일**로 계산해야 합니다. Sobel 점수와 같은 조건입니다.
  - 면을 재정렬·삭제하거나 좌표를 변환(예: UE 단위 변환)하려면 에너지를 계산한 **뒤가 아니라 전에** 하거나, 카메라도 같이 변환하세요.
- `cameras.json`이 없는 메시(예: 생성 모델 출력)는 촬영 카메라가 없으므로 PPQ를 쓸 수 없습니다.
  - 이 경우 `--method wild`를 쓰거나, `make_orbit_cameras.py`로 만든 전 방위 카메라를 `--cameras`에 넣어 "ExMesh 정보 없이" 같은 식을 적용할 수 있습니다. 이 변형은 평가하지 않았습니다.
- **UE5 텍스처 mip 주의**: 단순화기 bake 결과는 차트 둘레 1~2 텍셀만 채워지고 나머지는 검은색입니다.
  - UE5가 mip을 만들면 멀리서 볼 때(LOD가 쓰이는 거리) 차트 경계가 어두워질 수 있습니다. UE5 임포트는 UV 섬을 자동으로 확장(dilation)하지 않습니다.
  - 정제(`appearance_refine.py`) 출력은 빈 영역이 모두 채워져 있어 이 문제가 없습니다.
  - 정제를 쓰지 않는다면 임포트 전에 같은 edge padding을 적용하길 권합니다. 구현은 `appearance_refine.edge_padded`를 참고하세요.

## 8. 발견한 문제와 하위 호환성

### 8.1 외관 정제 v1의 이음새 버그 (수정함)

- **증상**: 첫 버전 정제는 자체 검증(nvdiffrast)에서 +2 dB였습니다. 그런데 팀 평가기에서는 정제 전 대비 결과가 이랬습니다(정제 4종 × 12개 조건).
  - PSNR −0.75~+0.51 dB: 대부분 나빠졌습니다.
  - LPIPS 1.3~2.0배: 모든 조건에서 나빠졌습니다.
- **원인**: 원본 2560² 아틀라스의 빈 영역은 검은색입니다.
  - mipmap 렌더에서는 이 검은색이 차트 경계로 번집니다. 그래서 정제의 목표 이미지(원본 렌더)에 원본 차트 경계를 따라 **어두운 이음새**가 생겼습니다.
  - 정제가 이 이음새를 새 텍스처에 그대로 학습했습니다.
  - mipmap이 없는 팀 평가기로 렌더하면 수염·모자에 가는 검은 선이 보였습니다.
  - 그림: `deliverables/enhanced_simplification/scan83_refine_v1_v2_seams.png`(원본 | Wild bake | 정제 v1 | 정제 v2, 3배 확대)
- **수정**: 원본과 결과 아틀라스 모두에 edge padding을 적용합니다. 차트 밖 텍셀은 항상 가장 가까운 차트 텍셀 값을 복사합니다.
  - 최적화 변수는 차트 안 텍셀뿐이고, 결과 텍스처도 패딩된 채 저장됩니다.
  - 그래서 UE5가 mip을 만들 때도 검은 번짐이 없습니다.
- **효과**:
  - scan83 20k 정제 전 검증 PSNR이 패딩만으로 41.5 → 45.2 dB로 올랐습니다. v1이 줄이던 오차의 상당 부분이 원본 이음새였다는 뜻입니다.
  - 팀 평가기 12개 조건에서 Wild 대비 PSNR:
    - 정제 tex: v1 −0.64~+0.14 dB → v2 −0.02~+0.81 dB
    - 정제 full: v1 −0.49~+0.51 dB → v2 +0.24~+0.94 dB
  - v2에도 팀 평가기 LPIPS 손실이 남아 있습니다. 다만 v1의 20~66% 수준이고 SS3와 비슷한 크기입니다. 이음새가 아니라 필터링 때문입니다(4.3).
- **공개 사항**: 이 수정은 평가 결과를 본 뒤 버그를 찾아 넣은 것입니다. 하이퍼파라미터는 바꾸지 않았습니다. v1의 메시와 평가는 `meshes/refine_v1/`, `evaluation/v1_refine_seams/`에 보존했습니다.

### 8.2 PPQ 입력 렌더의 같은 이음새 (수정함)

- PPQ도 원본 텍스처를 mipmap으로 렌더해서 기울기를 구합니다. 그래서 8.1과 같은 검은 번짐이 UV 이음새를 따라 가짜 기울기를 만들었습니다.
- 패딩 전후 에너지 비교:
  - scan24: 순위 상관 0.994, 가중치 평균 변화 1.3%
  - scan83: 순위 상관 0.945, 면 4.1%의 가중치가 25% 넘게 변화
- 고친 코드로 PPQ 에너지 계산, 단순화, bake, 정제, 평가를 모두 다시 했습니다. **4장의 수치는 모두 고친 버전입니다.**
- 이전 버전 대비 PPQ − Wild:
  - 평균은 +0.33 → +0.29 dB로 조금 줄었습니다.
  - 유의한 조건은 10/12 → 12/12로 늘었습니다. 예: scan83 1만 면 촬영 시점 −0.04 → +0.06 dB
- 이전 산출물: `outputs/DTU/<scene>/enhanced/archive_ppq_unpadded/`

### 8.3 평가기의 텍셀 좌표 규약 (참고, 수정하지 않음)

- `evaluate_mesh_preservation.render_cpu`는 텍셀 i를 u = i/(W−1) 위치에서 읽습니다(corner 규약).
- bake와 GPU·UE5는 텍셀 중심을 u = (i+0.5)/W에 둡니다.
- 그래서 1024² 아틀라스에서 최대 0.5 텍셀의 어긋남이 **모든 후보에 똑같이** 생깁니다.
  - 평가기를 GPU 규약으로 바꿔 보면 모든 후보의 PSNR이 약 0.25~0.3 dB 오르고 순위는 그대로였습니다(scan83 한 시점에서 확인).
  - 이전 Sobel 결과와 비교할 수 있도록 평가기는 고치지 않았습니다. 다음 실험부터는 GPU 규약으로 맞추길 권합니다.
- 단순화기의 `sample_texture_bilinear`(원본 텍스처 읽기)도 corner 규약입니다. 원본 2560² 기준 최대 0.5 텍셀(아틀라스 기준 0.2 텍셀)이라 영향은 작습니다.

### 8.4 평가 실행 시 주의: VRAM 초과

- `evaluate_mesh_preservation.py`는 프로세스마다 LPIPS(VGG)를 GPU에 올립니다. 768² 크롭에서는 프로세스당 약 3 GB를 씁니다.
- 12 GB GPU에서 6개를 동시에 돌리면 VRAM이 넘칩니다. 그러면 Windows가 공유 메모리로 페이징하고 속도가 100배 가까이 떨어집니다. 실제로 60뷰 평가 6개를 함께 돌리는 데 약 6시간이 걸렸습니다.
- **동시 실행은 3개 이하**로 하세요. 이번 결과는 3개씩 돌렸고, 라운드당 2~3분이었습니다.

### 8.5 그 밖의 문제

- **DTU 마스크 정렬**:
  - DTU `images/*.png`(1554×1162)는 1600×1200 원본을 (46, 38) 오프셋으로 잘라 주점을 중앙에 맞춘 이미지입니다.
  - 따라서 `mask/*.png`(원본 크기)를 리사이즈해 쓰면 어긋납니다. scan83에서 IoU가 0.82였습니다. 이미지 알파 채널이 정확한 마스크입니다.
  - ExMesh 학습은 원래 알파를 쓰므로 영향이 없습니다. 제 사진 평가 코드에서 이 문제를 발견해 고쳤습니다.
- **DTU 평가 스크립트**:
  - `scripts/eval_dtu/evaluate_single_scene.py`가 `python`을 그대로 호출합니다. 그래서 PATH의 시스템 파이썬(sklearn 없음)이 잡혀 실패할 수 있습니다.
  - `alt_models/run_exmesh_scene.py`는 env의 파이썬으로 `eval.py`를 직접 호출합니다.
- **TripoSR**: Windows용 패치 2개가 필요합니다(`alt_models/README.md`).

### 8.6 하위 호환성

- 새 옵션을 주지 않으면 결과가 이전과 같습니다. edge padding은 새 스크립트(PPQ, 정제)에만 들어가고, 단순화기 기본 출력은 바뀌지 않습니다.
  - 저장소의 scan24 Wild/Sobel 대조군(20k/10k/5k)을 새 코드로 다시 만들어 비교했습니다.

  - OBJ는 `mtllib` 줄(출력 파일 이름이 들어감)만 다르고 나머지는 같았습니다.
- 단위 테스트 26개가 통과합니다(`.ablation_env`, `PYTHONPATH=ExMesh;ExMesh/simplification`).
